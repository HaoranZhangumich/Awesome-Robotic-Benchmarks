# Contributing

Additions and corrections are both welcome. A fix to a wrong number or a dead link is as useful as a new entry.

## How the list is built

- Each entry is one YAML file in [`benchmarks/`](benchmarks/).
- The domains and sub-areas, and their order, are in [`taxonomy.yaml`](taxonomy.yaml).
- [`scripts/build_readme.py`](scripts/build_readme.py) writes `README.md` from those files.

So edit the YAML, then rebuild. Do not edit `README.md` by hand: the next build overwrites it.

## Add or fix an entry

1. Copy the template below into `benchmarks/<name>.yaml` (lower case, underscores).
2. Check it, including every link:

   ```bash
   pip install pyyaml
   python scripts/validate.py benchmarks/<name>.yaml
   ```

   The check prints the real title of every arXiv link next to your entry name, so a mistyped
   paper id is easy to spot. It should end with `0 FAIL`.
3. Rebuild the page and look at the result:

   ```bash
   python scripts/build_readme.py
   ```

4. Open a pull request with the YAML file and the rebuilt `README.md`.

## What belongs here

Something other people evaluate on or build evaluations from: a task suite, an evaluation protocol,
a dataset with standard splits or metrics, a leaderboard, a challenge. The Datasets and Simulators
sections also take datasets and simulators that the field trains and evaluates on.

Methods, models and surveys do not belong here.

## Template

For every domain except `Simulation`:

```yaml
name: LIBERO
domain: Manipulation            # a domain key from taxonomy.yaml
area: tabletop                  # a sub-area key under that domain
subtype: "table-top, lifelong learning"   # 1-3 short tags
first_release_date: 2023-06-05  # first public release: YYYY-MM-DD, YYYY-MM or YYYY
venue: "NeurIPS 2023 D&B"       # optional
widely_used: true               # optional: only for de-facto standards of the sub-area
description: "One or two plain sentences: what is evaluated and what sets it apart."
task_count: 130                              # a number, a short string, or 'N/A'
metric_count: "3 (FWT, NBT, AUC)"            # count, then the names in brackets
robot_config_count: "1 (Franka Panda)"       # count, then the names if there are 3 or fewer
modality: [RGB, proprioceptive, language]
setting: [sim]                  # [sim], [real] or [sim, real]
sim_backend: "robosuite (MuJoCo)"            # empty for real-world-only benchmarks
data_source:
  size: "50 human demos per task"            # 'N/A' if the benchmark ships no data
  collection_method: human_demonstration     # see below
resources:
  homepage: "https://libero-project.github.io/"
  paper: "https://arxiv.org/abs/2306.03310"
  code: "https://github.com/Lifelong-Robot-Learning/LIBERO"
  data: ""
  leaderboard: ""
```

`collection_method` is one of:

| value | meaning |
|---|---|
| `human_demonstration` | recorded from a person controlling the robot or simulator, or human motion capture |
| `human_annotation` | people wrote the questions or labels over existing sensor data |
| `motion_planner` | generated by a planner, inverse kinematics, a trajectory optimizer or a scripted expert |
| `synthetic` | generated programmatically or by generative models, no planner and no human |
| `rl_policy` | rollouts of trained reinforcement-learning policies |
| `mixed` | more than one of the above |
| `none` | the benchmark ships no data |
| `unknown` | not stated by the authors |

For the `Simulation` domain, the table compares capabilities, so the fields differ:

```yaml
name: MuJoCo
domain: Simulation
area: physics
first_release_date: 2012
description: "One or two plain sentences."
physics_engine: "MuJoCo"
renderer: "OpenGL"
gpu_support: true        # true only if the physics itself runs on the GPU for parallel environments
os: [Linux, Windows, macOS]
license: "Apache-2.0"
resources:
  homepage: "https://mujoco.org/"
  paper: ""
  code: "https://github.com/google-deepmind/mujoco"
  docs: "https://mujoco.readthedocs.io/"
```

## Rules of thumb

- Every link must be one you opened. Leave a field empty when there is nothing to link to.
- Put a number only where the paper or the project page states it. Otherwise write `N/A`.
- Keep table cells short (under about 80 characters) and the description under about 45 words.
- Links are bare URLs: nothing after the URL, no trailing spaces.
- `widely_used` is for benchmarks that a large share of papers in the sub-area report on. New releases
  earn it later.

## Add a sub-area or a domain

Add it to [`taxonomy.yaml`](taxonomy.yaml) (the order there is the order on the page), then use its key
in the benchmark files.
